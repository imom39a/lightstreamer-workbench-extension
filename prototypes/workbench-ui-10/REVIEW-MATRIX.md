# Integrated review matrix

Status: **accepted as implementation-ready on 2026-08-04**

Automated prototype verification is complete: all 19 named states render without shell overflow; compact/normal/shallow/wide frames and Dark/Light themes were exercised; Evidence roving focus and compact Context entry were verified; Source comparison has one shared scroll owner; invalid and retired-target Drafts cannot advance; and the browser console contains no application warnings or errors.

## Human review outcome

- **A — Diagnose accepted:** Capture, Coverage, View, Scope, ordered Evidence, selection, Context, and promoted documents read as one coherent developer-tool workflow.
- **B — Local Injection accepted:** one selected immutable Source becomes one explicit raw-JSON Local Draft, optional Source comparison, deliberate Review, and a persistent outcome without implying current multi-event editing.
- **C — Recover accepted:** degraded operation names the condition, affected Scope, Evidence limitation, safe conclusion, and nearby recovery route without creating an investigation stack.
- The product owner reviewed all three journeys live and explicitly accepted the integrated direction as implementation-ready.

## Corrections made during validation

- Made disconnected operation consistently state that Capture stopped while retained Evidence remains readable.
- Kept both full COMMAND projection names and contents available in compact layouts.
- Made Local Injection delivered and failed outcomes persistent and gave them outcome-appropriate next actions.

No correction changed the accepted UI standard or domain model; the prototype clarified their application.

## A — Diagnose incorrect application state

- orient on Capture, Coverage, Live/Frozen, current Scope, and retained counts;
- select ordered Server and Local Evidence without conflating focus or provenance;
- open Context, raw Evidence, and distinct COMMAND projections;
- Freeze high-volume history without stopping Capture;
- reach scoped export without making it a permanent destination;
- preserve an understandable empty current Scope.

## B — Reproduce or vary behavior with Local Injection

- enter from one selected Captured Item Update;
- keep immutable Source, prospective Draft, exact target, validation, and Local-only boundary visible;
- edit raw JSON with optional one-scroll Source comparison;
- distinguish invalid or retired target from an attempted failure;
- review exact Draft and target before deliberate Local Injection;
- report delivered locally or failure without claiming application/business success;
- retain trace to Injected Update and Local Effective COMMAND State only.

## C — Understand degraded operation

- name the affected Scope, condition, evidence limit, and safe conclusion;
- keep retained historical Evidence readable while disabling invalid action boundaries;
- separate Capture operation, Coverage, Live/Frozen position, and runtime lifecycle;
- keep recovery close without clearing history, following Live, retargeting, or discarding a Draft.

## Cross-cutting review

- compact `563×700`, normal `900×700`, shallow `900×320`, and wide `1440×900`;
- representative Dark and Light themes;
- orientation time, context preservation, Evidence traceability, action reachability, error recovery, keyboard operation, and semantic accuracy;
- no shell horizontal scroll, no hidden consequential action, no icon-only meaning, no traffic-light COMMAND semantics, and no investigation stack.
