## How agents use the improved interface

The complete call contract and examples are in [agent/READS.md](../../agent/READS.md). A typical investigation is:

1. Discover the exact Panel Session, page epoch and Scope. Inspect the advertised Injection capability before constructing a candidate.
2. Read a narrow Scope with explicit fields, typed predicates and a frozen read point. Continue with its opaque cursor. Use a sequence window for a known experiment interval.
3. Use `aggregate_evidence` for counts or buckets, `query_command_rows` to discover active rows, and `query_command_keys` to compare exact keys. Deliberately select observed-server or local-effective state and inspect certainty/provenance.
4. Use `read_bundle` when several reads must share a boundary. Handle each result's error or alignment limitation; a bundle cannot contain an effect or arbitrary tool call.
5. Generate and validate an explicit candidate matrix. Prepare a Draft or Scenario separately using a stable request ID. Recover an interrupted publication instead of preparing another document.
6. Execute Local Injection once and inspect the returned committed Evidence identity. Use exact Run/revision waits for Scenario progress and suffix waits for subsequent captured Evidence.
7. For a Server experiment, prepare an exact Client Message and let the developer review and approve the visible document. Execute with the same request ID; retrieve the receipt after uncertainty.

Query work defaults to 250,000 projection reads, 1,000 payload hydrations and a 15-second deadline at the agent boundary; callers can supply bounded alternatives. A breached budget returns `QUERY_WORK_BUDGET_EXCEEDED`, not a partially evaluated exact count. Serialized MCP results default to 8 KiB, with offered larger ceilings up to 64 KiB. Continuations retain their originating response contract. Fixed read bundles share a deadline and bound each subread; up to eight operations are not an unlimited computation allowance.

Candidate matrices are limited to 100 expanded Steps and 8 MiB; exact key lists contain at most 32 keys. COMMAND row pages contain at most 100 rows, key comparisons at most 32 keys, and field selections at most 32 names. Bounded waits run for at most 20 seconds. These limits keep the interface useful within one temporary Panel Session.

## Semantics and review corrections

Native Lightstreamer Item Updates expose full field values as well as changed-field APIs. Therefore generated changed-field behavior remains meaningful for callback fidelity. Removing it would hide a real distinction used by application listeners. Captured original bitmaps remain intact; the correction applies to authored or edited delivery.

The loaded extension was tested with official Lightstreamer Web Client 9.2.3 against a dedicated fixture server. Actual application listeners verified named/positional values and flags plus full/changed-field iteration. COMMAND ADD includes concrete null fields; same-key UPDATE distinguishes equal values; DELETE preserves its key and command while clearing other values. Source-free MERGE and DISTINCT tests verify concrete null, snapshot assignment and equal-value subsequent delivery. These are callback proofs, not claims that Local Injection reproduced server-side business logic.

Independent correctness review found and reproduced five additional integration defects, all corrected with regression coverage: nested JSON-string credentials could influence predicate counts; an approved agent Server send could begin with a hidden panel; an old Server receipt could attach another message's outcome; deferred Local field loading could omit part of a temporal absence window; and Pause during that loading could leave the Run permanently frozen. Stop during a late temporal query is also guarded. The independent recheck verifies the credential and Server corrections; the runner tests verify the loader, Pause/Play and Stop behavior. Review and recheck evidence (`.scratch/mcp-agent-audit/evidence/independent-spec-review.md`, local artifact).

A final React review also corrected a misleading select fallback when a human returned an agent-authored field/absence checkpoint to Edit. Those two assertion kinds now display their actual kind and every parameter as explicitly read-only; the existing Add/Remove route lets the human replace an assertion deliberately. Returning to Review preserves the exact definition. This is an agent-authoring capability with truthful inspection in the human editor, rather than a newly added UI authoring form. The focused normal/shallow forced-colors packet passes browser and independent visual review. Component review (`.scratch/mcp-agent-audit/evidence/react-component-review.md`, local artifact).

Supplemental predicates and grouping redact recognized credential fields and recursively encoded JSON credentials before evaluating values, preventing an inference oracle through counts. Canonical captured Evidence stays observationally intact. Unknown, absent, ambiguous, concrete null and redacted values retain distinct meanings.

Server approval is one-use, fingerprint-bound and invalidated by edits, Session drift or access revocation. Visibility and live ownership are rechecked immediately before sending. `Processed` describes the Lightstreamer Client Message outcome; downstream application effects and attribution of later Server Updates require the application's own contract.

## Explicit limits and conditional decisions

- RAW generation remains explicitly unsupported, as approved, pending its own verified native delivery contract. Generated second-level COMMAND and JSON Patch fidelity are refused or explicitly limited; captured-source replay remains separate.
- Retain the locked MCP SDK 1.30.1 and defer MCP Tasks. The supported SDK/stdio client matrix passes; no named supported host establishes a need for a migration or longer-lived task protocol. This is the approved conditional outcome for ticket 21.
- Evidence and Scenario waits do not wake a host after their bounded call ends. Hidden, revoked, disposed or changed targets cannot authorize a new effect.
- Absence assertions prove only an adequate captured observation window. Missing coverage, gaps, retention or target drift produce inconclusive results. Local field assertions inspect correlated committed Local Evidence, not the application's DOM or business state.
- Predicates and aggregates do not combine with Find or facet discovery; callers can perform separate reads at the same frozen boundary. Group limits and missing logical IDs are reported explicitly.
- No Claude Desktop or other third-party host UI, Windows/Linux runtime, general Chrome query-latency distribution, Long Task budget, physical-memory bound or model-token benchmark was verified. The durable tests and reproduction commands establish the narrower behavior described above.
- Changes are local and uncommitted. Deployment, npm publication and Chrome Web Store publication are outside this implementation.
